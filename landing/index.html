uma história em quatro passos

Seu computador não precisa aguentar tudo sozinho.

01 · O GARGALO

Você roda 10 agentes. O computador trava.

Dez tarefas do Claude Code ou do Codex ao mesmo tempo: cada uma compila, roda testes e indexa o projeto. A CPU vai a 100%, a memória enche, a ventoinha dispara e a tela congela.

Você para de trabalhar e espera tudo voltar ao normal.

02 · UM AMIGO AJUDA

Um amigo tem uma máquina sobrando.

No escritório ao lado ou do outro lado do mundo, pela internet. Ele roda um comando e empresta processamento, CPU e memória, para as suas tarefas:

carbon join https://seu-painel --token cjt_…

Só entra quem tem o token de join que você gerou. Você pode pausar ou remover a máquina dele a qualquer momento.

03 · A FILA SE ESPALHA

As tarefas se espalham. O seu computador respira.

O painel manda cada tarefa para um computador livre: o notebook do amigo, um servidor Linux, uma sessão do AWS AgentCore. Cada um roda o agente na própria CPU.

A sua CPU volta para o verde, e você continua trabalhando.

04 · TUDO VOLTA PARA VOCÊ

Os resultados voltam para o seu painel.

Cada computador devolve um branch. O painel mostra log, diff e testes como se tudo tivesse rodado aqui, e abre o PR para você revisar.

Mais computadores, mais tarefas ao mesmo tempo, e você decide com um clique.

CPU 100% · 10 agentes · tudo travado

Um ticket entra. Oito estágios depois, sai um PR.

Cada tarefa roda num git worktree isolado. O agente reporta progresso por um protocolo simples, e o painel mostra tudo em tempo real: plano, comandos, testes e pedidos de permissão.

    LOCAL-FIRST

    Seus dados ficam na sua máquina

    SQLite local, servidor só em 127.0.0.1, senhas com scrypt. Vários projetos, cada um com sua fila e base.

    MULTI-AGENTES

    Uma tarefa, vários sub-agentes em paralelo

    Marque Usar multi-agentes se necessário e o agente divide o que for independente em até 4 sub-agentes, cada um com seus arquivos. O principal integra e roda os testes. O painel mostra quem está rodando e o que cada um está fazendo, ao vivo.

    integrações

    Peça no chat. Responda com um clique.

    Mencione o bot no Slack ou no Telegram, ou ponha uma label numa issue do Jira: a tarefa entra na fila. Quando o agente precisa decidir, a pergunta chega com opções. Você clica, e ele continua de onde parou, no mesmo worktree.

    • JIRA CLOUD

      Label ou /carbon

      Issue com a label carbon ou um comentário /carbon … vira tarefa. O Carbon comenta o andamento, faz as perguntas e move o status até “Em revisão”.

    • SLACK

      @carbon no canal

      Atualizações na thread da menção e perguntas com um botão por opção, com a recomendada em destaque.

    • TELEGRAM

      /carbon no seu chat

      Só o chat autorizado cria tarefas e responde. As perguntas chegam com botões, direto no celular.

    • LINEAR E GITHUB

      Importe issues

      Importe na nova tarefa; o link do PR volta comentado no Linear.

    Webhooks por túnel HTTPS, aceitos só com a assinatura de cada serviço. Tokens ficam no banco local e nunca voltam ao navegador.

    harness

    28 skills de engenharia, instaladas em cada tarefa.

    O agente não depende de boa vontade: em cada etapa ele segue skills que transformam boas práticas em passos verificáveis. Teste falhando antes do fix, revisão com severidade, segurança, LGPD, migrações reversíveis, verificação antes de entregar. Adaptadas do Everything Claude Code para o protocolo do Carbon.

    eficácia

    Quanto o agente está ajudando, medido.

    O Mission Control mostra se vale a pena: quantas tarefas terminam bem, quantas viram PR, quantas rodam sem precisar de você, plano cumprido, testes verdes, achados críticos resolvidos, tempo e custo médios. Tudo calculado do que o Carbon registra, com as fórmulas à vista. Sem dado, aparece “sem dados”, nunca um palpite.

    inspiração e créditos

    De onde veio a ideia.

    DEEPSEEK-AI / DSH-SUPERAGENT-PROTOTYPE
    Menos atenção humana, mais valor entregue.

    O Carbon nasceu da filosofia do dsh-superagent-prototype, da DeepSeek: um agente que leva uma tarefa de ponta a ponta, com etapas explícitas, memória e reflexão, e que chama o humano só quando há decisão a tomar. Aqui essa ideia virou uma plataforma web local, ligada ao seu Linear, ao seu GitHub e aos agentes de código que você já usa.

    • Claude Code e Codex CLIOs executores. O Carbon orquestra; eles escrevem o código. Basta ter um dos dois.
    • Everything Claude CodeBase das 28 skills nativas do harness: TDD, verificação, revisão, segurança e mais, adaptadas ao protocolo do Carbon.
    • ascii-revealAs animações de decodificação em caracteres do painel (MIT).
    • GeistTipografia sans e mono.
    • E o nome: carbono, o elemento que se liga a quase tudo. Como um agente que se conecta ao seu fluxo.

    execução distribuída

    Escale para outras máquinas e para a AWS.

    Por padrão, uma tarefa por vez no seu computador. Com workers, várias tarefas rodam ao mesmo tempo em outros servidores ou em outro computador da sua rede (direto pelo IP, sem servidor), e o painel continua sendo o centro: fila, log ao vivo, perguntas, permissões e entrega aparecem nele como numa tarefa local. Para colocar um servidor novo, é um comando, como no Docker Swarm.

    LOCAL

    Esta máquina

    O padrão. Fila serial, sem rede, nada muda para quem já usa.

    POOL

    Cluster de workers

    Gere um token de join no painel e rode carbon join (ou um docker run) em cada servidor. Vale URL ou ip:porta, pela rede local ou pelo IP público. Ele entra sozinho, recebe credencial própria e começa a pegar tarefas. Pause, retome ou remova servidores pelo painel.

    skill para claude code · experimental

    Sua sessão do Claude Code chama reforço.

    A skill carbon-coop pareia um servidor seu como servidor Orca e manda partes do trabalho para lá. Os workers usam o Claude Code deste computador, e o resultado volta como branch para você revisar. Não precisa do painel do Carbon: só de Orca, ssh, git e Node 22+.

    claude · sessão coordenadora
    1. /carbon-coop connect carbon@meu-servidor
    2. preflight: orca 1.4.253 · ssh por chave · node 22
    3. proxy do Claude Code em 127.0.0.1:8787 (login fica aqui)
    4. túnel SSH aberto · orca-ide serve em 127.0.0.1
    5. pareado como coop-meu-servidor
    6. manda os testes do módulo de auth pro servidor
    7. enviado o commit a1f3c9e (mudanças não commitadas ficam aqui)
    8. worker rodando no servidor · encerro o turno, o Orca me acorda
    9. worker terminou: 3 commits, 14 testes passando
    10. branch coop-meu-servidor/coop/auth-tests pronto para revisar

    começar

    Dois minutos, um terminal.

    O setup interativo checa o ambiente, detecta o agente instalado, cria seu perfil e já indexa o repositório. Depois é só abrir o navegador.

    # 1. clone e instale
$ git clone https://github.com/leolegends/carbon-superagent
$ cd carbon-superagent && npm install

# 2. setup interativo (ou pelo navegador em /setup)
$ npm run setup

# 3. sobe em http://127.0.0.1:3417
$ npm start
