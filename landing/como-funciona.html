Execução distribuída, passo a passo

O código está no seu computador. Como outro servidor ajuda?

O servidor recebe só o que a tarefa precisa: o pedido e uma cópia do código já commitado. Ele trabalha numa cópia isolada, devolve um branch e apaga a cópia. Nada entra no seu projeto sem você decidir. Escolha o seu caso e avance os passos.

Passo 1

O que viaja e o que nunca sai do seu computador

↗ Vai para o servidor

  • O pedido: título, descrição, decisões que você já respondeu, regras de permissão do repositório.
  • O código commitado do branch base: clonado do GitHub/GitLab, ou em um pacote git (bundle) baixado do painel.
  • Contexto do projeto: skills do Carbon e o mapa do projeto (arquivos relevantes).

■ Fica no seu computador

  • Mudanças não commitadas na sua pasta e arquivos ignorados pelo git (como o .env).
  • O seu branch atual: o servidor devolve o trabalho num branch agent/… separado.
  • A decisão: merge, PR ou aplicar na pasta é sempre você quem faz.
  • Seus tokens: o token da máquina e o de git são tirados do ambiente antes do agente rodar.

Perguntas rápidas

Preciso abrir porta no servidor?

Não. Quem abre a conexão é o servidor: ele pergunta ao painel se há tarefa (por HTTPS). O que precisa ser alcançável é o painel: pela rede local, pelo IP público, por VPN ou por um túnel SSH aberto do seu computador, sem nenhuma porta aberta na internet.

E se o servidor cair no meio da tarefa?

O servidor renova a posse da tarefa a cada ~20 s. Se parar de renovar, a tarefa falha com o motivo (ou volta para a fila, se você configurar). O seu repositório não é tocado: o trabalho só entra quando o resultado chega completo.

Com repositório sem GitHub, como o código vai?

O painel monta um pacote git (bundle) com o commit base e o servidor baixa do próprio painel. O resultado volta do mesmo jeito: um pacote com o branch da tarefa, que o painel importa no seu repositório. Repositório sem nenhum commit também funciona: a base é uma cópia dos arquivos que respeita o .gitignore.

Que modelo o servidor usa?

O Claude Code ou o Codex instalados e logados no servidor. Em modo experimental, ele pode usar o login do Claude Code deste computador por um proxy local, sem copiar a credencial para o servidor.

E o meu código fica no servidor?

Só enquanto a tarefa roda: ao terminar, a cópia é apagada. Mesmo assim, o código passa pela máquina: use servidores que você controla e que podem receber esse repositório.
